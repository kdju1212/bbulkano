광고 계정 통합 모니터링 대시보드 — 기획안
(작성일 2026-07-18, 나중에 구현할 기능. 아직 코드 없음)

====================================================
목적
====================================================
네이버·구글·카카오·메타 광고 API를 연동해서, 광고계정 -> 캠페인 -> 그룹 ->
소재/키워드를 웹사이트 한 화면에서 확인하는 기능.
- 캠페인명·그룹명·소재/키워드명, ON/OFF 상태, 일예산, 운영 시간(스케줄)을 표시
- "지금 켜져있어야 할 시간인데 꺼져있는" 스케줄 불일치를 감지해서 표시
- 알람(이메일/카카오톡/슬랙 등 자동 발송)은 이번 범위에서 제외 — 우선 "보기"
  기능만 만들고, 알람은 나중 단계에서 이 판정 로직을 재사용해서 추가한다.

====================================================
플랫폼별 조사 결과
====================================================

[네이버]
- SA(검색광고)와 DA(디스플레이, GFA)가 API 자체가 완전히 분리되어 있음.
  검색광고 API와 GFA API는 인증도 엔드포인트도 따로.
- 검색광고 API는 셀프서비스: 광고주가 [도구] > [API 사용관리]에서 약관 동의만
  하면 라이선스 키·비밀키 즉시 발급. 별도 심사/승인 없음.
- 대행사가 여러 광고주를 보려면: 각 광고주가 대행사 계정에 "권한위임"을 해줘야
  함. 대행사 자신의 키 하나로 위임받은 여러 계정을 조회하는 구조라 계정별로
  키를 따로 발급받을 필요는 없어 보임.
- 단, 위임받을 수 있는 광고주 수(검색 결과상 최대 5개로 보임)와 동시에
  조회/관리 가능한 계정 수(1개, 계정 전환 필요할 수 있음)에 제한이 있다는
  정보가 있었음. 공식 문서 직접 접근이 403으로 막혀 2차 자료로만 확인됨 —
  실제 구현 전 네이버 공식 문서/고객센터로 재확인 필요. 특히 관리 광고주가
  5개를 넘는 경우 중요한 변수.

[구글]
- Google Ads API 하나로 SA/DA 둘 다 커버 (캠페인 유형 SEARCH/DISPLAY로 구분).
- MCC(관리자 계정) 구조로 여러 광고주 계정을 한 번에 조회 가능 — 에이전시용으로
  설계된 기능이라 가장 매끄러움.
- 개발자 토큰 신청 필요 (Google 승인 절차 있음, Basic access면 충분할 것으로
  보임).

[카카오]
- 카카오모먼트 오픈API 하나로 SA/DA 커버 (캠페인 유형으로 구분).
- **"카카오 광고 공식대행사"만 API 신청 가능** — 아무 계정이나 쓸 수 있는 게
  아니라 카카오 채널 담당자를 통해 별도 권한 신청/승인이 필요한 진짜
  게이트키핑 절차가 있음. 카카오 디벨로퍼스에서 모먼트 전용 앱을 만들고
  "비즈 앱"으로 전환해야 권한 부여 가능.
- 지금 대행사가 카카오 공식대행사로 이미 등록돼있는지가 관건. 안 돼있으면
  이 절차부터 별도로 밟아야 함 (우리가 대신 처리 불가).

[메타]
- 검색광고 개념이 없어서 전부 DA로 분류.
- Marketing API로 캠페인/광고세트(AdSet)/광고 상태·예산·스케줄
  (adset_schedule, day-parting) 조회 가능.
- 비즈니스 관리자(Business Manager)에 클라이언트 계정을 파트너 권한으로
  연결해두면 인증 한 번으로 여러 계정 조회 가능 — 구글과 비슷하게 에이전시
  표준 워크플로우.
- 액세스 토큰이 60일마다 만료돼서 주기적 갱신 필요 (자동화하거나 수동 재발급).

====================================================
인프라 / 아키텍처
====================================================
- DB 불필요. "보기" 기능은 페이지를 열 때마다 각 플랫폼 API에서 실시간으로
  데이터를 가져와서 화면에 뿌리고, 저장하지 않음. 지금 GA4 대시보드/UTM
  빌더/네이버 관리와 동일한 패턴.
- API 키·토큰은 지금처럼 환경변수(.env / Render 환경변수)로 관리.
- 대행사가 여러 광고주(A기업/B기업/C기업)를 관리하는 경우:
  - 구글/메타: 인증 한 번(MCC/비즈니스 관리자)으로 연결된 여러 계정 커버 가능.
  - 네이버/카카오: 광고주 계정별로 키를 따로 등록해야 할 가능성 높음. 이 경우도
    DB는 필요 없고, RAW 가공이 광고주별 폴더(pipelines/dongkook,
    pipelines/gangchon, pipelines/kg-eduone)로 관리되는 것과 같은 패턴으로,
    광고주별 키 목록을 파일 하나에 정리해두는 정도로 충분.
- "여러 사람이 같은 계정들을 같이 보는" 것(팀원들이 로그인해서 회사가 관리하는
  광고주들을 조회)이라면 DB 불필요. "각자 자기 광고 계정을 직접 연결"하는
  진짜 멀티테넌트 SaaS 구조라면 DB 필요 — 지금은 전자로 가정.
- 스케줄 불일치 감지도 크론/DB 없이 페이지 로드 시점에 클라이언트에서 실시간
  계산 가능 (이미 API로 가져온 스케줄 데이터와 현재 시각을 비교). 나중에
  알람(자동 발송) 기능을 추가할 때만 크론 작업 + 최소한의 중복 알림 방지용
  저장소가 필요해짐.

====================================================
화면 구성
====================================================

전체 구조: SA / DA 탭 토글 (UTM 빌더의 키워드/캠페인·그룹/DA 탭과 같은 패턴).
탭을 바꾸면 트리 전체가 바뀜.
- 네이버: SA 탭엔 검색광고 API 데이터만, DA 탭엔 GFA 데이터만.
- 구글/카카오: 같은 계정이 캠페인 유형에 따라 SA/DA 탭에 각각 다른 캠페인으로
  나타남.
- 메타: DA 탭에만 나타남 (SA 탭엔 안 보임).

표 칼럼: 광고계정 | 캠페인 | 그룹 | 소재/키워드
(상태/일예산/시간을 별도 칼럼으로 빼지 않고, 각 이름 옆에 인라인으로 표시)

각 칸의 표시 규칙:
- 펼쳐진 상태: "이름 + 그 항목 자체의 ON/OFF + 일예산 + 시간"
  예) 여름세일_SA  🟢 ON · 5만원/일 · 09-21시
  없는 값(그룹 단위 예산이 없는 플랫폼 등)은 "—"로 표시.
- 접힌 상태(광고계정, 또는 소재/키워드가 접혀있을 때): 해당 칼럼이 그 레벨의
  집계로 바뀜. "켜짐 N · 꺼짐 M" 형태.
  예) 광고계정이 접혀있으면 캠페인 칼럼엔 "켜짐1·꺼짐1"(캠페인 2개 기준),
      그룹 칼럼엔 "켜짐4·꺼짐2"(그룹 6개 기준), 소재 칼럼엔 "켜짐20·꺼짐3"
      (소재 23개 기준) — 세 칼럼에 각자 그 레벨의 집계가 따로 찍힘.
  예) 그룹이 소재를 접어두고 있으면 소재 칼럼엔 "켜짐10·꺼짐2" 형태로 표시
      (기존에 생각했던 "소재 12개" 같은 단순 개수 표기가 아니라 ON/OFF
      분리 표기로 확정).

펼침/접힘:
- 펼치고 접을 수 있는 지점은 광고계정, 소재/키워드 두 곳뿐. 캠페인과 그룹은
  광고계정을 펼치면 같이 다 보임 (수량이 적을 것으로 가정, 별도 접기 없음).
- 최대 2번 클릭으로 소재/키워드까지 도달 (계정 펼치기 -> 소재 펼치기).
- 상태를 기억하지 않음 — 페이지 진입/새로고침 시 항상 초기값으로: 광고계정은
  펼쳐진 채로 시작, 소재/키워드는 접힌 채로 시작.

필터:
- 캠페인 / 그룹 / 소재 칼럼 헤더 옆에 각각 ON/OFF 필터 [전체 / ON만 / OFF만]
  (네이버 소재 리스트화의 캠페인/광고그룹/소재 ON-OFF 필터와 같은 패턴).
- 광고계정 칼럼엔 필터 없음 (계정 자체는 ON/OFF 개념이 없음).
- 필터를 걸어도 자동으로 트리가 펼쳐지지 않음 — 사용자가 직접 펼쳐야 함.

스케줄 불일치 표시:
- 스케줄상 "지금 켜져있어야 하는데 실제로 꺼진" 항목의 행에 라벨 추가.
  예) 일반검색그룹  🔴 OFF ⚠ 스케줄 불일치 · 2만원/일 · 09-21시
- 표 바깥 상단, 항상 보이는 위치에 빨간 배너로 전체 불일치 건수 표시.
  예) "⚠ 스케줄 불일치 3건"
- 배너를 클릭하면 불일치가 있는 광고계정들이 한 번에 펼쳐짐. 이후 세부 내용은
  표에 이미 붙어있는 "⚠ 스케줄 불일치" 라벨을 보고 확인.

====================================================
나중 단계 (이번 범위 아님)
====================================================
- 실제 알람 발송 — 이메일/카카오톡 알림톡/슬랙 중 채널 선택 필요. 위에서 만든
  스케줄 불일치 판정 로직을 크론이 주기적으로 돌리는 방식으로 확장.
- 중복 알림 방지용 최소 저장소 필요 (같은 항목이 계속 꺼져있다고 매번 알람
  가지 않도록).
- 상시 운영 vs 기획전(단기) 캠페인 구분 필터 — 각 플랫폼의 캠페인 기간(종료일)
  설정 여부로 1차 판별 가능 (종료일 있으면 단기, 없으면 상시로 추정. 완벽하진
  않음 — 캠페인명 패턴 매칭으로 보조 가능).

====================================================
구현 시작 시 우선순위 제안
====================================================
네이버가 진입장벽이 가장 낮음 (셀프서비스, 승인 절차 없음). 단, 위임 계정 수
제한을 먼저 확인해야 함. 구글/메타는 에이전시 구조(MCC/비즈니스 관리자)가
깔끔하지만 개발자 토큰/앱 심사 절차가 있음. 카카오는 공식대행사 인증 여부부터
확인 필요.
